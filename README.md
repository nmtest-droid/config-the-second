# Dependency Graph CLI

Консольное приложение для получения метаданных NuGet, построения
транзитивного графа зависимостей, обнаружения циклов, вычисления порядка
загрузки и генерации графического представления в D2 и SVG.

## Требования

- Python 3.10 или новее.
- Для удалённого режима нужен NuGet V3 Service Index.
- D2 CLI (`d2`) необязателен. Если он доступен в `PATH`, приложение
  использует его для генерации SVG. Иначе работает встроенный SVG-рендерер.
- Runtime использует только стандартную библиотеку Python. NuGet CLI,
  менеджеры пакетов и сторонние Python-библиотеки для извлечения
  зависимостей не применяются.

## Запуск

Linux и macOS:

```bash
./run.sh --help
```

Windows:

```bat
run.bat --help
```

Пример локального тестового запуска:

```bash
./run.sh \
  --package A \
  --repository tests/fixtures/graphs/branching.json \
  --test-repo-mode on \
  --version 1.0.0 \
  --show-load-order \
  --output dependency-graph.svg
```

Для удалённого NuGet V3-репозитория укажите Service Index и выключите
тестовый режим. Каталог вывода должен существовать заранее:

```bash
mkdir -p build
./run.sh \
  --package Newtonsoft.Json \
  --repository https://api.nuget.org/v3/index.json \
  --test-repo-mode off \
  --version 13.0.1 \
  --show-load-order \
  --output build/newtonsoft-json.svg
```

Приложение выводит конфигурацию, список вершин и рёбер, сведения о циклах,
а при включённом `--show-load-order` — dependency-first порядок. Для каждого
графа рядом с SVG-файлом сохраняется исходник D2 с тем же базовым именем.

## Параметры командной строки

| Параметр | Назначение |
|---|---|
| `--package` | Имя анализируемого пакета |
| `--repository` | URL NuGet V3 Service Index или путь к JSON-графу |
| `--test-repo-mode` | `on` — локальный тестовый граф, `off` — NuGet V3 |
| `--version` | Точная версия корневого NuGet-пакета |
| `--output` | Путь к выходному SVG-файлу |
| `--show-load-order` | Дополнительно вывести порядок загрузки зависимостей |

В тестовом режиме параметр `--repository` должен указывать на существующий
JSON-файл. Имена пакетов в тестовом графе состоят только из заглавных
латинских букв `A-Z`. Все ссылки на зависимости должны вести к объявленным
вершинам.

Пример файла списка смежности:

```json
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": ["D"],
  "D": []
}
```

Подготовленные тестовые сценарии:

| Файл | Сценарий |
|---|---|
| `chain.json` | Цепочка `A → B → C` |
| `branching.json` | Ветвление и общая транзитивная зависимость |
| `cycle.json` | Цикл `A → B → C → A` и отдельная ветвь `D` |
| `self-loop.json` | Зависимость вершины от самой себя |
| `isolated.json` | Изолированная вершина без рёбер |

## Получение данных NuGet

В удалённом режиме приложение запрашивает NuGet V3 Service Index, находит
ресурс `PackageBaseAddress/3.0.0`, получает индекс доступных версий и
загружает `.nuspec` для конкретной версии пакета. Для корневого пакета
используется версия из `--version`. Для транзитивной зависимости выбирается
максимальная опубликованная версия, удовлетворяющая диапазону из `.nuspec`.

Поддерживаются точная версия и основные диапазоны NuGet: `[1.2.3]`,
`[1.0.0, 2.0.0)`, `[1.0.0, )` и простая минимальная версия `1.0.0`.
Для сложных конфликтов зависимостей прототип не заменяет полноценный
NuGet restore resolver.

## Алгоритмы графа

### Итеративный DFS

Граф строится алгоритмом поиска в глубину без рекурсии. Используется явный
стек кадров и три состояния вершин:

- `white` — вершина ещё не посещалась;
- `gray` — вершина находится в активном стеке DFS;
- `black` — все исходящие рёбра вершины обработаны.

Ребро в серую вершину является обратным ребром и фиксирует цикл. Обход
продолжается после обнаружения цикла, поэтому остальные достижимые вершины
также добавляются в граф. Повторные зависимости устраняются с сохранением
порядка. Сложность обхода достижимой части графа — `O(V + E)`, где `V` —
число вершин, `E` — число рёбер.

В NuGet-режиме вершина идентифицируется парой `PackageId@Version`. В
тестовом режиме используются заданные буквы `A-Z`.

### Порядок загрузки

Порядок вычисляется топологической сортировкой алгоритмом Кана. Ребро
`A → B` означает, что пакет `A` зависит от `B`, поэтому `B` должен быть
загружен раньше `A`. Корневой пакет исключается из печатаемого списка.

Если граф содержит цикл, полный топологический порядок невозможен.
Приложение выводит безопасную часть порядка и отдельно указывает вершины,
заблокированные циклической компонентой или зависимые от неё.

## Визуализация D2 и SVG

После построения графа приложение:

1. Создаёт текстовое описание графа на языке диаграмм D2.
2. Сохраняет `.d2` рядом с выходным SVG-файлом.
3. Генерирует `.svg` через D2 CLI или встроенный SVG-рендерер.

Направление рёбер сохраняет модель зависимостей: `Package → Dependency`.
Корневой пакет выделяется синим цветом, вершины и рёбра обнаруженных
циклов — красным. `--output` принимает только расширение `.svg`; исходный
файл D2 получает такое же имя с расширением `.d2`.

Три воспроизводимых примера для разных корневых пакетов `A`, `B` и `C`
описаны в [`examples/README.md`](examples/README.md). Команды создают
изображения в `build/`; сгенерированные файлы намеренно не включены в Git.

## Сравнение со штатными средствами NuGet

Команда .NET SDK `dotnet package list --include-transitive` показывает
прямые и транзитивные пакеты, но выводит плоский список, а не связи между
парами пакетов и не SVG-диаграмму. Наш инструмент показывает направленные
рёбра и может сохранить их в D2/SVG. Поэтому состав пакетов можно
сопоставить со списком `dotnet package list`, но все рёбра нельзя
восстановить только из табличного вывода.

Также возможны различия в разрешении версий. Прототип выбирает максимальную
опубликованную версию для каждого диапазона зависимости независимо.
NuGet PackageReference использует собственные правила разрешения, включая
`lowest applicable version` и `direct-dependency-wins`, и учитывает
целевые платформы. В проектах с конфликтами версий или несколькими TFM
состав разрешённого графа может отличаться.

Фактический запуск `dotnet restore` и D2 CLI зависит от установленного на
машине инструментария. В среде подготовки проекта эти бинарные файлы
недоступны; поведение приложения проверяется локальными HTTP-фикстурами,
юнит-тестами и встроенным SVG-рендерером.

## Тестирование

Запуск всех автоматических тестов:

```bash
make test
```

Альтернативный запуск без Make:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Сетевые сценарии используют локальный HTTP-сервер. Тесты NuGet не требуют
доступа к `api.nuget.org` и не запускают менеджеры пакетов.

## Очистка и файлы, исключённые из Git

```bash
make clean
```

`.gitignore` исключает кэши и служебные файлы Python, виртуальные среды,
артефакты сборки, архивы, файлы редакторов, а также создаваемые `.d2` и
`.svg`. Для воспроизводимой демонстрации используйте команды из
`examples/README.md`, а не добавляйте результаты генерации в репозиторий.
